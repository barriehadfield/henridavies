# CLAUDE.md — Henri Davies site

Static portfolio website for the artist **Henri Davies** (paintings, photography,
fashion). Migrated from a WordPress.com site; served as a **static GitHub Pages
site from the repo root**. Plain HTML/CSS/JS — no framework, no runtime deps.

Design: a single **dark charcoal** identity (no light theme), **coral** accent/CTA
(`#ff6f49`), image-first galleries where each image sits "raised" on the surface, a
landing home page, and a full-screen **swipe + pinch-zoom** lightbox.

## Mental model

Three layers — you almost never hand-edit the middle or bottom one:

```
DATA (edit this)              →  BUILD (scripts)     →  OUTPUT (committed, don't hand-edit)
scripts/site-data.mjs             npm run build          index.html, paintings.html, …
source/images/<section>/*         npm run optimize       public/images/<section>/*
```

- **`scripts/site-data.mjs`** — the single source of truth for content
  (`PAINTINGS`, `PHOTOGRAPHY`, `FASHION`, `FOR_SALE`, `ABOUT_PARAS`, `SOCIAL`).
- **`source/`** — full-resolution originals (archive) + `source/reference/`
  (original page HTML captured from the old site, incl. the Fashion article).
  Committed on purpose; everything lives in one repo.
- **`public/images/`** — web derivatives generated from `source/`. **Generated —
  do not edit by hand.** Regenerate with `npm run optimize`.
- **`*.html` at repo root** — the actual pages. **Generated by
  `scripts/build-pages.mjs` — do not hand-edit.** Edit the data/templates and run
  `npm run build`.
- **`css/style.css`, `js/site.js`** — hand-written, the real site assets.

## Pages

`index.html` (landing — hero + section cards) · `paintings.html` · `photography.html`
· `fashion.html` (article-led) · `for-sale.html` · `about.html`.
`paintings-for-sale.html` is a **redirect stub** → `for-sale.html` (old URL).

## Commands

```bash
npm install        # once — installs sharp (build-time only, a devDependency)
npm run optimize   # source/images/**  ->  public/images/**  (after adding/replacing originals)
npm run build      # regenerate all root *.html from build-pages.mjs
npm run dev        # no-cache static server at http://localhost:8000  (see below)
```

**Serve with `npm run dev`, not `python3 -m http.server`.** `scripts/dev-serve.py`
sends `no-store` headers so a normal browser refresh always shows freshly built
files; the plain server lets the browser cache css/js and "changes don't show".

There is **no test suite**. "Verify" = build, serve, and screenshot with headless
Chrome (`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless
--screenshot=… --window-size=W,H <url>`). Note: headless Chrome enforces a **~500px
minimum viewport**, so screenshots narrower than that get clipped on the right —
use `--window-size=600,…` (still under the 720px mobile breakpoint) for mobile.

## Image pipeline (`scripts/optimize-images.mjs`)

For every original in `source/images/{paintings,photography,fashion,site}/` it emits
four files into the matching `public/images/…` folder:

| file | purpose |
|------|---------|
| `<name>.webp` / `<name>.jpg`             | full-size (max edge 2000px), webp + jpeg fallback |
| `<name>-thumb.webp` / `<name>-thumb.jpg` | gallery thumbnail (max edge 800px) |

- To add a new section folder, add its name to the `SUBDIRS` array.
- EXIF orientation is respected; originals are never modified.

## Page generator (`scripts/build-pages.mjs`)

Builds every page from a shared `layout()` + the data imported from `site-data.mjs`:

- `NAV` — top nav (Paintings, Photography, Fashion, For Sale, About). Wordmark → home.
- `buildHome()` is a **landing** (hero + three `roomCard` section entries), *not* a
  gallery. `buildPaintings/Photography/Fashion/ForSale/About` build the rest.
- Each gallery item is `{ file, title? }`; `title` optional (untitled → no caption,
  generic alt). **Array order = display order.** Append new works to the arrays.
- `dims()` reads width/height from the `-thumb.jpg` so every `<img>` gets
  `width`/`height` → no layout shift.
- `tile()` → `<a class="tile" … data-full="…webp" data-title="…">`. **The lightbox
  in `js/site.js` collects `.tile[data-full]` in document order**, so any
  lightbox-able image must use that shape; the sequence is the swipe order.
- Fashion leads with the press article (`fashion-01`) as an editorial hero, then
  grids `FASHION.slice(1)`.

## Front-end (`css/style.css`, `js/site.js`)

- **One dark theme** — committed, no toggle. Palette + elevation are CSS custom
  properties at the top of `style.css`: `--accent` (coral), `--edge-top` / `--lift`
  drive the raised-image look. Change those tokens to retune globally.
- **Lightbox is PhotoSwipe v5** (vendored at `js/vendor/photoswipe/`, no CDN).
  `js/site.js` is an ES **module** (`<script type="module">`) that imports it and
  inits on `main` / `a.tile`. Tiles need `data-pswp-width`/`data-pswp-height` (the
  **full**-image dims — `fullDims()` in the generator reads them from `<file>.jpg`);
  `data-title` becomes the caption. To update the library: `npm i -D photoswipe@x`
  then re-copy `dist/{photoswipe.esm.js,photoswipe-lightbox.esm.js,photoswipe.css}`.
- Mobile nav is a fixed full-height panel; it needs an explicit `height:100dvh`
  because the header's `backdrop-filter` makes it the panel's containing block.

## Conventions & gotchas

- **Relative asset paths** (`public/images/…`, `css/…`) — required because Pages
  serves the project at `…/henridavies/`. Never use root-absolute `/…` paths.
- **No em-dashes** in visible copy (user preference); **UK spelling**.
- **Fashion image ordering** is encoded in the filenames `fashion-01…51` (curated
  order from the article); `fashion-01` (press scan) must stay first. See `CONTENT.md`.
- **Fashion originals are PNG scans** (heavy). A future perf pass could add AVIF +
  responsive `srcset` — see the redesign proposal artifact.
- `.nojekyll` is present so Pages serves files as-is.
- `CONTENT.md` is the human content manifest; keep it in sync when content changes.

## Deploying

GitHub Pages → Settings → Pages → Deploy from branch → `main` / root. Live at the
custom domain **`henridavies.com`** (cut over; `CNAME` + DNS point at Pages). Commit
the generated `*.html` and `public/` — they are what Pages serves.

**SEO** is generated in `layout()` from `SITE_URL` (`https://henridavies.com`): each
page gets a canonical URL, per-page `<meta description>`, Open Graph + Twitter card
tags with a representative absolute `og:image`, and the home page carries a
`WebSite`/`Person` JSON-LD block whose `sameAs` are the `SOCIAL` links. `npm run
build` also writes `sitemap.xml` (all real pages) and `robots.txt`. If the domain
ever changes, update `SITE_URL` and rebuild.

The **share card** (`DEFAULT_OG_IMAGE`, used for the home page + any page with no
section image of its own) is a dedicated 1200×630 image. Its design source is
`source/og-card.html` (committed, system-font stacks matching `style.css`); it is
rendered to `public/images/site/og-card.jpg` with headless Chrome — see the
comment at the top of that HTML file for the exact command. It is **not** produced
by `npm run optimize`; re-render it by hand only if the card design changes.
