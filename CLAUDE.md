# CLAUDE.md — Henri Davies site

Static portfolio website for the artist **Henri Davies** (paintings, photography,
fashion). Migrated from a WordPress.com site; served as a **static GitHub Pages
site from the repo root**. Plain HTML/CSS/JS — no framework, no runtime deps.

## Mental model

There are three layers, and you almost never hand-edit the middle or bottom one:

```
DATA (you edit this)          →  BUILD (scripts)        →  OUTPUT (committed, don't hand-edit)
scripts/build-pages.mjs data       npm run build            index.html, photography.html, …
source/images/<section>/*          npm run optimize         public/images/<section>/*
```

- **`source/`** — full-resolution originals (the archive) + `source/reference/`
  (original page HTML captured from the old site, incl. the Fashion article).
  Committed on purpose; the user wants everything in one repo.
- **`public/images/`** — web derivatives generated from `source/`. **Generated —
  do not edit by hand.** Regenerate with `npm run optimize`.
- **`*.html` at repo root** — the actual pages. **Generated by
  `scripts/build-pages.mjs` — do not hand-edit.** Edit the data/templates in that
  script and run `npm run build`.
- **`css/style.css`, `js/site.js`** — hand-written, the real site assets.

## Commands

```bash
npm install        # once — installs sharp (build-time only, a devDependency)
npm run optimize   # source/images/**  ->  public/images/**   (run after adding/replacing originals)
npm run build      # regenerate all root *.html from build-pages.mjs
python3 -m http.server 8000   # preview at http://localhost:8000
```

There is **no test suite**. "Verify" = build, serve, and screenshot with headless
Chrome (`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless
--screenshot=... --window-size=W,H <url>`). Note: headless Chrome enforces a
**~500px minimum viewport**, so screenshots narrower than that get clipped on the
right — use `--window-size=600,…` (still under the 720px mobile breakpoint) to
check mobile layouts.

## Image pipeline (`scripts/optimize-images.mjs`)

For every original in `source/images/{paintings,photography,fashion,site}/` it emits
four files into the matching `public/images/…` folder:

| file | purpose |
|------|---------|
| `<name>.webp` / `<name>.jpg`         | full-size (max edge 2000px), webp + jpeg fallback |
| `<name>-thumb.webp` / `<name>-thumb.jpg` | gallery thumbnail (max edge 800px) |

- To add a new section folder, add its name to the `SUBDIRS` array.
- EXIF orientation is respected; originals are never modified.

## Page generator (`scripts/build-pages.mjs`)

Builds every root HTML page from a shared `layout()` + per-page data. Key spots:

- `NAV` — the nav shown on every page. Add/remove/reorder links here.
- `PAINTINGS`, `PHOTOGRAPHY`, `FASHION`, `FOR_SALE`, `ABOUT_PARAS` — page content.
  Each gallery item is `{ file, title? }`; `title` is optional (untitled works
  render without a caption). **Array order = display order.**
- `dims()` reads image width/height from the `-thumb.jpg` (proportional to the
  full image) so every `<img>` gets `width`/`height` → no layout shift.
- `tile()` renders a `<a class="tile" … data-full="…webp">` with a `<picture>`
  (webp + jpg thumb). **The lightbox in `js/site.js` collects `.tile[data-full]`**,
  so any clickable, lightbox-able image must use that shape.
- Fashion leads with an editorial hero (the press article = `fashion-01`) via
  `buildFashion()`, then grids `FASHION.slice(1)`.

## Conventions & gotchas

- **Relative asset paths** (`public/images/…`, `css/…`) — required because Pages
  serves the project at `…/henridavies/`. Never use root-absolute `/…` paths.
- **Fashion image ordering** is encoded in the **filenames** `fashion-01…51`,
  renamed from the article's `image26, image13, …` curated order. `fashion-01` is
  the press-feature scan and must stay first. See `CONTENT.md` for the mapping.
- **Fashion originals are PNG scans** (heavy). A future perf pass should move to
  JPEG/WebP/AVIF + responsive `srcset` — see the redesign proposal.
- `.nojekyll` is present so GitHub Pages serves files as-is.
- `CONTENT.md` is the human content manifest (bios, prices, social links, gallery
  order). Keep it in sync when content changes.

## Deploying

GitHub Pages → Settings → Pages → Deploy from branch → `main` / root. Live target
is `henridavies.com` (custom domain, not yet cut over). Commit the generated
`*.html` and `public/` (they are what Pages serves).

## Where things are going

A redesign is under discussion (neutral gallery frame, mobile swipe-first, faster
